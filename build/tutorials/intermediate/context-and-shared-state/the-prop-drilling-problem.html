The Prop Drilling Problem

What context is for, and the cheaper fixes worth trying first.

Props flow down one level at a time. When a value is needed five levels deep, every component in between has to accept it and pass it on, even though none of them use it. That is prop drilling.

It is not just ugly. Every intermediate component now has a prop it must keep in its type definition, and renaming the value means touching all of them.

Try composition first

Advertisement

Prop drilling often disappears if you pass the finished element instead of the data. The component that owns the data creates the child, so nothing in between needs to know.

Tip

Reach for composition before context. It keeps data flow explicit and does not add a new indirection to trace when you are debugging.

When context earns its place

  • Values genuinely needed everywhere: theme, locale, the current user, feature flags.
  • Values that change rarely, so re-render cost is low.
  • Compound components where a parent must talk to distant children, such as tabs or accordions.

Watch out

Context is not a state manager. It is a way to deliver a value down the tree. Frequently changing data in a widely used context re-renders large parts of your app.
